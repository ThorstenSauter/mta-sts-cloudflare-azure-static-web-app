## What this is

A reusable Terraform **module** (not a root configuration) that sets up MTA-STS (RFC 8461) and TLS-RPT for a domain whose DNS is on Cloudflare. It hosts the policy file on an Azure Static Web App. `example/` is a root configuration that consumes the module via `source = "../"`.

## Commands

No tests exist. CI (`.github/workflows/terraform-validate-and-docs.yml`) runs these checks on PRs, and they are the same ones to run locally from the repo root:

```sh
terraform init -backend=false
terraform fmt -check -recursive
tflint --init && tflint --no-color -f compact   # uses .tflint.hcl (azurerm ruleset)
terraform validate -no-color
```

To exercise the module end to end, run `terraform init/plan/apply` in `example/`. This needs Azure and Cloudflare credentials, an existing Cloudflare zone, and Node.js.

## Architecture (all in `main.tf`)

- **Policy rendering:** `mta-sts.tftpl` is rendered with `mode`, `mx_records` and `max_age` into `.terraform/tmp/wwwroot/.well-known/mta-sts.txt` under `path.root`, which is the *caller's* root module. `index.html` is copied next to it. That directory is exposed as the `deployment_directory` output.
- **Policy ID:** `local.policy_id` is an md5 of the rendered policy (`local.policy_content`). It goes into the `_mta-sts` TXT record (`v=STSv1; id=...`) and also triggers redeploys, so any change to the template or its inputs rolls out automatically.
- **DNS / custom domain ordering:** Cloudflare CNAME `mta-sts.<domain>` → SWA default hostname, then `time_sleep.record_creation` (`wait_for_dns_propagation`), then `azurerm_static_web_app_custom_domain` (cname-delegation). The custom domain reads its name from `time_sleep`'s `triggers`, which forces the wait to happen first.
- **Content deployment:** `terraform_data.deploy_content` runs a `local-exec` provisioner: `npx` with the pinned SWA CLI (`local.swa_cli_package`) calls `deploy <content dir> --env production`. The SWA API key goes in through the `SWA_CLI_DEPLOYMENT_TOKEN` environment variable, so it never appears on the command line. The command is shell-agnostic (it works under `cmd.exe` and POSIX shells). Keep `--env production`; without it the CLI deploys to a preview environment. The resource re-runs when `index.html`'s md5 or `policy_id` changes.
- The SWA ignores changes to `repository_*` attributes because content is pushed with the deployment token, not from a linked repo.

## Conventions

- Input variables in `variables.tf` carry `validation` blocks (domain format, MX host pattern per RFC 8461 §4.1, `rua` scheme `mailto:`/`https:`, lifetime ≤ 1 year, and so on). Keep adding validations for new inputs.
- The `README.md` section between `<!-- BEGIN_TF_DOCS -->` and `<!-- END_TF_DOCS -->` is generated by terraform-docs in CI and pushed back to the PR branch. Don't hand-edit it.
- `.terraform.lock.hcl` is intentionally gitignored because this is a module.
- Dependency updates come from Renovate (`chore(deps): ...` commits). Commit messages follow Conventional Commits.
- `.editorconfig`: LF line endings, 2-space indent, UTF-8.
